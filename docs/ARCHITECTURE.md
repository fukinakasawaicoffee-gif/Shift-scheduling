## レイヤー構成

### 1. プレゼンテーション層 (Frontend)

**技術**: React, TypeScript, Material-UI

**役割**:
- ユーザーインターフェースの提供
- ユーザー入力の検証
- APIとの通信

**主要コンポーネント**:

- `Components/`: 再利用可能なUIコンポーネント

### 2. API層 (Backend - FastAPI)

**技術**: FastAPI, Pydantic

**役割**:
- RESTful APIエンドポイントの提供
- リクエスト/レスポンスの検証
- 認証・認可
- エラーハンドリング

**主要モジュール**:
- `api/auth.py`: 認証エンドポイント
- `api/departments.py`: 部署管理API
- `api/employees.py`: 従業員管理API
- `api/schedules.py`: スケジュール管理API

**技術**: Python

**役割**:
- ビジネスルールの実装

- データ変換・集計

**主要モジュール**:
- `services/schedule_service.py`: スケジュール生成サービス

### 4. 最適化層

**技術**: Google OR-Tools

**役割**:
- 制約付き最適化問題の定義
- シフト割り当ての最適化
- 制約充足確認

**主要モジュール**:
- `optimizer/shift_optimizer.py`: シフト最適化エンジン

### 5. データアクセス層

**技術**: SQLAlchemy

**役割**:
- データベースアクセス
- ORM操作
- トランザクション管理

**主要モジュール**:
- `models/`: SQLAlchemyモデル
- `schemas/`: Pydanticスキーマ
- `core/database.py`: DB接続管理

## シフト最適化アルゴリズム

### 制約付き最適化問題としての定式化

**決定変数**:
- `shifts[e, d, s]`: 従業員eが日付dにシフトsを担当するかどうか（0/1変数）

**制約条件**:

1. **1日1シフト制約**:
   ```
   ∀e,d: Σ(s) shifts[e,d,s] ≤ 1
   ```

2. **必要人数制約**:
   ```
   ∀d,s: Σ(e) shifts[e,d,s] ≥ required[d,s]
   ```

3. **休日制約**:
   ```
   ∀e: Σ(d,s) shifts[e,d,s] ≤ total_days - max_holidays - leave_days[e]
   ```

4. **連続勤務制約**:
   ```
   ∀e,d: Σ(i=0 to max_consecutive) Σ(s) shifts[e,d+i,s] ≤ max_consecutive
   ```

5. **休暇申請制約**:
   ```
   ∀e,d ∈ approved_leaves[e]: Σ(s) shifts[e,d,s] = 0
   ```

**目的関数**:
```
minimize: max_work_days - min_work_days
```
（従業員間の勤務日数の偏りを最小化）

### ソルバー

Google OR-ToolsのCP-SAT (Constraint Programming - SAT) ソルバーを使用

**特徴**:
- 制約充足問題に特化
- 高速な求解
- 整数変数のみで定義可能
- 複雑な論理制約の表現が容易

## セキュリティ

### 認証・認可

- **JWT (JSON Web Token)** を使用したトークンベース認証
- パスワードは **bcrypt** でハッシュ化
- トークンの有効期限: 7日間

### CORS設定

- 開発環境: `localhost:3000`, `localhost:8000`を許可
- 本番環境: 必要なオリジンのみを明示的に許可

### SQL Injection対策

- SQLAlchemy ORMによるパラメータ化クエリ
- Pydanticによる入力検証

## パフォーマンス

### 最適化戦略

1. **データベース**:
   - インデックスの設定（employee_code, date など）
   - クエリの最適化

2. **API**:
   - 非同期処理（FastAPIのasync/await）
   - ページネーション

3. **フロントエンド**:
   - React Queryによるキャッシング
   - コンポーネントの遅延ロード

### スケーラビリティ

- 従業員200名程度まで対応
- シフト生成: 1ヶ月分を5分以内（通常は数十秒）
- 水平スケールが可能な設計

## デプロイメント

### コンテナ構成

- `backend`: FastAPIアプリケーション
- `frontend`: Reactアプリケーション（開発サーバー）
- `db`: PostgreSQLデータベース

### 環境変数

主要な環境変数:
- `DATABASE_URL`: データベース接続文字列
- `SECRET_KEY`: JWT署名用秘密鍵
- `REACT_APP_API_URL`: APIエンドポイントURL
